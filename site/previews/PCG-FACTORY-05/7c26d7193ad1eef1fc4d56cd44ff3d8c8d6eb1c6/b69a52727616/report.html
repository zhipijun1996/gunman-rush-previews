PCG-FACTORY-05：离线 Module 生产与真人评审入口

本轮交付离线生产器、可行/不可行行为档案、独立留出筛选、真实试玩评分页面与反馈回收工具。当前有4个通过普通难度技术门槛、等待真人评审的候选；真实人评0，已批准离线模块0。 没有修改正式游戏、Map Notes 或正式模块池。

实际生产流程

  1. 从基础Cell与已实现能力推导动作词，生成平台/钩点/荆棘/锯轮/载人平台参数。
  2. 用真实Godot组件执行。校准集同时评价预期动作、稳定出口、完整身体危险接触、输入扰动与载人证据。
  3. 按真实动作词、水平换向与静止等待比例建立行为格。可行档案保留校准表现较好的候选；不可行档案保留约束距离较小的候选，两区实际供下一轮变异。
  4. 对预先选定、几何去重的候选，一次性运行独立初相位/扰动留出和有限较低成本替代策略。不用留出失败来重选幸运种子或返修后重复考同一组题。
  5. 技术合格候选进入盲评入口。真人亲自操作后评分、保存、导出；回收工具验证模块/目录版本，生成返工任务；明确的人工决定才可进入实验离线库。

这是自实现的有界MAP-Elites基线与FI式双档案搜索，不是完整复现某篇FI论文，也没有调用pyribs、训练神经网络或在线调用大模型。规则、挑战家族与指标仍由开发者定义；AI辅助开发和独审，生成/模拟/入库由程序执行。

行为格来自已执行的动作与轨迹，不是模块ID、地形标签或随机种子。动作词顺序参与格键；同一几何不因多种控制策略重复进入最终候选。6个格不是“6种已验证有趣玩法”，也没有据此声称覆盖全部游戏体验。

分批运行后保留完整原始输入与输出：每批输出压缩保存，记录压缩前长度/SHA256与压缩文件SHA256，不丢弃失败轨迹。工作源在运行前复制完整文本字节，658份文本源与清单绑定目录；870份受保护原件核对零漂移。二进制素材与Godot引擎不重复塞进快照，按固定游戏提交/不可变base及完整哈希恢复。快照单独不等于完整游戏资产包。

该批次含搜索、校准、留出及替代策略成本；不能据此保证任意区域的每模块生产时间。相比旧批次，分批减少了单个Godot进程的轨迹积累，但批量和工作量不同，不报告公平的百分比性能提升。当前未提供断点续跑CLI；中断时已完成批次及源快照仍会保留。

一次真实的不可行→可行改进

搜索从不可行档案选中一个载人平台＋二段跳候选，将接收台、目标和制动目标一起向左移动32wu。角色物理、能力、平台运动与资源规则不变；仍要求实际登船、零轴搭乘、离船跳与二段跳。

同相位/噪声计划下的自动策略 原父代 生成子代
校准无扰动 0/4 4/4
校准轻扰动 2/4 4/4
独立无扰动初相位 0/12 12/12
独立轻扰动 6/12 12/12
独立中扰动 5/12 10/12

校准前后是搜索自身使用的数据；父代独立对照另外运行36次，子代复用已经冻结的留出数据，未返还给搜索。证据为 factory-parent-comparison-v1。这是通关与容错改进，不证明子代更有趣，也不代表搜索已经能发明任意机制。

距离函数包含动作编辑距离、目的失败、危险、连续性/搭乘、完成情况以及到出口中心的软目标。因包含软目标，合格候选仍可能有很小的正数距离；是否可行由明确的动作/物理门槛决定，不以距离恰好等于0代替验收。

严格普通门槛与4个待评候选

固定策略版本2默认请求 regular：无扰动通过率至少.90，轻扰动至少.85，中扰动至少.65；每档至少12次，纯静态无扰动基准只需1次。发现较低成本通路时先进入设计返工，不能自动证明所有替代都不好。精密挑战必须在运行前显式选择 --tier precision_review，不能把普通门槛失败事后改名高难成功。

初版v1按两个工程档分类，含1个仅符合precision的候选。独立审查后，factory-production-v2 沿用同6个候选、同留出统计与同反例，只收紧为明确请求的regular；不改几何、不重挑候选、不重跑物理。保留v1原始分类，派生分类与门槛源另存。

各项是自动观察反馈控制器的表现，不是人的成功率。12次有限抽样的置信区间很宽，不能证明所有相位可靠。质量档案同时保留Wilson区间、样本数、原始轨迹引用和失败原因。97个有限替代测试没有找到便宜路线，也不能证明剩余模块的动作必要性。

真人筛选与反馈闭环

网页默认只显示4个技术合格候选，使用打乱的样例编号；完整技术分数在保存自己的评价后再展开，减少第一印象干扰。可评趣味、可读性、公平性、重玩意愿和感受难度，并记录问题与自由文字。无需通关即可评价；必须有实际手动输入记录，单看Replay不算亲自操作。

评价只保存在当前浏览器，不会自动上传。导出JSON并发回后才能进入回收。每份反馈绑定整个质量目录、具体模块哈希及试玩表现源；几何、能力、输入见证、镜头或界面发生变化时旧反馈不能冒充新版本评审。无需真实姓名，使用代号即可。Web目录另派生表现绑定，不覆盖原技术目录，导入时使用随试玩发布的catalog.json。

客户端记录与代号是未签名自报，不构成身份认证。导入不会自动批准；默认至少2个不同代号的报告，再由明确人工策展决定确认，才能标记实验离线库保留；即使如此 formal_game_ready 仍为false，正式消费者/区域/设备验收另行进行。

导入、生成返工任务示例（收到真实反馈文件后使用）：

python3 -m prototype.factory.feedback_cli import \
  --catalog delivery/factory-v1/web-release/catalog.json \
  --store review/feedback.json --file module-feedback.json
python3 -m prototype.factory.feedback_cli repair-job \
  --catalog delivery/factory-v1/web-release/catalog.json \
  --store review/feedback.json --out review/repair-job.json
python3 -m prototype.factory.core.producer --name factory-next-run \
  --repair-job review/repair-job.json \
  --repair-catalog delivery/factory-v1/web-release/catalog.json \
  --repair-cases results/factory-production-v2/review_cases.json

当前自动消费两类局部返工：落点难读→扩大接收面；锯轮等待过长→缩短周期。所有子代重新物理/扰动/反例验证，区域约束仍可拒绝。非锯轮的等待问题、无聊、控制问题或需要重新设计的捷径转人工设计任务，不用无关参数变异冒充修复；可读性不只由接收面宽度决定，真人仍需复评。

本轮使用真实键盘操作测试了网页与导出，测试模式明确输出 synthetic_test。正常导入拒绝该数据；诊断store不能批准或驱动真实生产。独立测试把这份合成反馈转换为带 test_only 的任务，再实际变异并经Godot重验1个子代，通过目的检查；生产候选写入0、真实人评0、批准0。测试链路已跑通，不等于已经发生真人评审。

最终本地发布候选在Chromium中通过5次真实输入回放（首个基线和全部4模块）、手动操作、评分解锁、导出、正常入口拒绝合成报告、测试store隔离和重载保留草稿；页面/引擎错误0。当前界面绑定反馈实际驱动的诊断在 factory-feedback-loop-test-v2，之前界面错误与修订记录也保留。这里的“手动操作”指浏览器自动化实际发送键盘输入，不是人类试玩。原始证据含合成声明，不能计入产品评分。

代码、复现与边界

  • prototype/factory/core/producer.py：从Cell生成、校准质量搜索、双档案变异、独立留出和有限反例。
  • core/quality.py：真实行为特征、档案与显式门槛；core/engine.py：源快照、受保护原件检查、分批与完整压缩轨迹。
  • derive_catalog.py：严格派生，不改旧数据；compare_repair.py：父代独立配对诊断。
  • core/feedback.py / feedback_cli.py：版本绑定、导入、返工、明确人工决定与测试隔离。
  • main_factory.gd：在冻结V3场景上增加观察与消息，不改Motor/资源；web/为本地保存和导出的评分界面。
  • 独立审查见 research/factory-audit.md，原始复算脚本和收据见 evidence/factory-audit/。
